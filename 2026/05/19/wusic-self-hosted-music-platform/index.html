📌 项目概述

Wusic 是开源托管于 GitHub 的一个音乐服务相关项目，其目标是构建一个自托管的音乐服务器系统，包括后台服务、管理界面和播放器等组件。虽然目前该项目处于初期阶段且完善度不高，但它的架构设计和代码结构仍具有一定的参考价值。

📎 项目仓库：github.com/wilgaboury/wusic

🧠 一、项目定位与整体目标

Wusic 的愿景是创建一个完整的音乐平台框架，包括以下主要部分：

组件 说明
🎧 后端服务（REST API） 管理音乐库、播放队列、用户信息等业务逻辑
🛠 Web 管理界面 用于管理音乐内容、播放列表和设置
📱 播放器（客户端） 支持用户播放音乐、浏览列表、交互操作

项目采用模块化设计，将不同功能拆分为独立子项目，使得各个部分能在未来灵活组合。

仓库目录结构

该项目既包含后端 Go 服务代码，也包括前端（TypeScript/CSS/HTML）和资源文件。

📦 二、核心组成与技术栈

1. 后端服务（Go 语言）

技术 用途
Go 编写 REST API，承担服务器逻辑
chi / 类似框架 路由处理 HTTP 请求
SQLite 轻量级数据库存储音乐元数据、用户信息
Protobuf 定义服务交互数据结构

后端核心职责：

  • 处理音乐文件元数据解析
  • 播放列表 CRUD 逻辑
  • 用户认证与权限管理
  • 音乐流媒体传输

2. 前端 Web 管理界面

技术 说明
SolidJS / React 现代响应式前端框架
TypeScript 类型安全的业务逻辑
CSS / Tailwind 样式与布局

前端核心功能：

  • 音乐库浏览与搜索
  • 播放列表管理
  • 系统设置配置
  • 调用后端 API 显示动态内容

3. 播放客户端（规划中）

README 中提到 Jetpack Compose Android 播放器 的计划，未来可实现：

  • 跨平台播放（Android / iOS / Desktop）
  • 通过 REST 接口获取播放列表和音乐流
  • 离线缓存与同步

📖 三、源代码原理与实现思想

项目设计遵循模块化分层原则：

1. 协议定义层（protos/）

使用 Protobuf 定义 API 请求与响应格式，使服务逻辑与数据结构明确且可扩展：

2. REST 后端架构

  • 路由层：定义各 HTTP 路径（如 /songs, /playlists, /stream 等）
  • 服务层：封装音乐数据查询、修改、验证逻辑
  • 存储层：通过 SQLite 管理音乐元数据、用户信息、状态等

3. 前端界面逻辑

  • 发起对后端 API 的请求
  • 使用响应式界面组件更新播放状态、列表信息
  • 实现状态管理（当前播放、下一首、搜索等）

整体遵循前后端分离架构，后端专注数据与业务逻辑，前端负责展示与用户交互。

🧾 五、项目现状与建议

🟡 仓库尚处于 “未完成状态”，尚不稳定可用，建议：

优先级 建议
🔴 高 完善后端接口和前端 UI 基础功能
🔴 高 补充音乐流处理逻辑与静态文件服务
🟡 中 编写单元测试和自动化 CI 流程
🟢 低 添加 Docker 容器化部署支持

即使作为学习项目，它仍提供以下参考价值：

  • ✅ 后端 API 设计规范
  • ✅ Protobuf 协议定义实践
  • ✅ 前后端分离架构模式
  • ✅ Go + Web 全栈项目组织方式

🧪 总结

Wusic 是一个自托管音乐平台开源项目，通过模块化设计整合后端服务、前端管理和未来播放器模块。

尽管尚未完工，但它展示了：

  • 📁 清晰的代码组织方式 — back/、front/、protos/ 分离
  • 🔌 协议定义 + REST API + 前端 UI 的分层开发逻辑
  • 🏗 如何利用现有工具构建全栈音乐系统的思路

对于想要学习 Go 后端 + 前端全栈开发 的开发者，这是一个不错的参考项目。
